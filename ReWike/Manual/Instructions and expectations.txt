Objective: Convert user stories or requirements into BDD (Behavior Driven Development) test cases.

Instructions:
1. Analyze the provided user story/requirement to identify the key functionalities and expected behavior.
2. Based on the input parameters, generate the specified number of BDD test cases in Gherkin syntax.
3. Ensure that the generated test cases cover the specified test case type.

Reference Suggestions:
- "Given-When-Then" format best practices
- Examples of BDD in Agile methodologies
- Resources on writing effective user stories

Thought Process with Sub Tasks:
1. Identify User Story Elements: Break down the user story into its core components (actors, actions, outcomes).
2. Determine Test Case Validity: Assess which scenarios are reasonable (positive, negative, edge) based on the user story.
3. Draft Scenarios: Write out the scenarios using Gherkin syntax, ensuring clarity and completeness.
4. Review and Revise: Check the generated test cases for accuracy, completeness, and adherence to BDD standards.
5. Output the Test Cases: Ensure the final output is formatted correctly and includes the specified number of test cases as requested.

Output:
- Provide a list of BDD test cases formatted correctly in Gherkin syntax based on the input parameters, ensuring clarity and comprehensive coverage of the user story elements.
